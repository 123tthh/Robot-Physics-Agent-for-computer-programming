# VF-01-T04：批环境隔离与吞吐

状态：`DONE`（固定诊断负载的 1/16/64 环境范围），2026-09-26。本项把固定工位、固定骨盆、单手直接关节控制扩展为同一 PhysX 场景中的 1、16、64 个工位。每个工位有 G1 + Dex5、74 键实体键盘、桌椅，以及独立的控制令牌、事件桥、文本状态、验证队列和随机数流。使用 Isaac Sim 5.1 / Isaac Lab 2.3.2，复用 T02 的物理参数与 T03 的反馈契约。

范围是有完整证据的批量诊断与资源测量。没有训练 PPO，没有把策略状态缓冲区称为已训练的循环网络，也没有把模拟文本读数当成桌面或机器人相机反馈。

## 工程结构

| 模块 | 位置（相对 `src/vskill_os/`） | 职责 |
|---|---|---|
| 批量配置与行状态 | `learning/batch.py` | 冻结规模/间距/缓冲容量、稳定种子派生、独立 RNG 和策略状态 |
| 批量物理场景 | `adapters/isaac/learning/batch_scene.py` | 克隆工位、碰撞分组、张量行映射、被动键帽、局部状态写入 |
| 控制与文本协调 | `adapters/isaac/learning/batch_env.py` | 原子动作校验、逐子步安全、逐行事件/反馈、局部 reset |
| 原始记录 | `adapters/isaac/learning/batch_recording.py` | 有界分块 NPZ、每回合压缩 JSON、哈希 |
| 冻结诊断 | `adapters/isaac/learning/batch_smoke.py` | 混合触键/静止/数字扰动、待反馈时重置、旧令牌拒绝、吞吐 |
| 独立复核 | `adapters/isaac/learning/batch_verify.py` | 对全部原始行重算时间、物理、安全、事件、反馈及重置隔离 |
| 外部进程管理 | `adapters/isaac/learning/batch_runner.py` | 每规模独立 worker、超时、GPU 占用采样、异常与报告 |

核心只依赖标准库；NumPy 用于可选记录与离线读取，依赖组为 `learning-batch`。Isaac、Torch 和 USD 仅进入适配器。T02/T03 收集器保持原字节，旧证据可按原版本复核；批量 USD 使用独立的 `artifacts/verification_feedback/assets/batch_usd/`。

## 物理与逻辑隔离

工位以 3 m 网格间隔克隆，每个环境的碰撞分组仅允许本组与公共地面。Articulation 和接触传感器的张量行必须对应 `/World/envs/env_i`；不能依靠字符串排序猜测 `env_10` 与 `env_2` 的关系。离线检查还用工位原点与键帽世界位置核对行身份。

每个控制周期接收与环境行数相同的动作。所有行先完成关节映射、令牌、序号、期限、限位和限速检查，再写入任何目标。即使最后一行使用旧令牌，也不会让前面的工位先走一步。策略观察仍由 T03 白名单构造，不包含原始事件、文本真值、隐藏扰动或成功标签。

物理以 240 Hz 推进，控制周期为 4 个物理子步。每个子步读取所有 69 维关节状态及 74 键的键程、接触和世界位置；初始化、静止工位和等待反馈期间均执行独立安全检查。当前诊断遇到任一安全失败会终止本规模 worker，单独保存触发拒绝的完整批状态、物理步与失败代码，并刷新此前原始块，不继续统计成功吞吐。它不是支持任意异步终止/自动 reset 的 Gym/PPO 训练封装。

键事件样本身份包含**环境、回合、物理步、键名**，避免事件桥把同帧其他键错误去重。任何被事件桥拒绝的样本都使收集失败，不能静默丢失。原始事件仍引用同一物理帧，供独立阈值回放。

## 局部重置

先对所有工位做 240 个安全检查下的稳定子步，保存每个工位的关节位置、速度、根状态与命令目标。后续局部 reset 恢复选定工位自己的缓存，**不推进物理时间，也不再次为它单独稳定 240 步**。这样相邻工位不会发生未记录的动作或时间跳变。

重置前先封存旧回合并取消待返回请求；新回合清空事件桥、文本、读数、验证预算、上一动作与策略状态，更新控制令牌。RNG 由 `(base_seed, env_index)` 独立派生，不调用全局重新播种。相同工位的 RNG 序列不随批大小变化；这不意味着 GPU 物理在不同世界坐标下必须逐位相同。

记录包含重置前后的**完整批量原始数组**和逻辑状态。独立检查要求未选中的工位数组逐位相等，时钟、事件数、动作数、RNG 指纹、策略状态和反馈预算也完全相同；选中工位的关节状态必须等于它的稳定缓存。新的所有权拒绝旧动作和旧验证请求。

诊断在第一个控制周期后重置第 0 行，此时请求尚未返回。该旧回合被标为取消，不能算作成功的按下/释放。新回合随后完整触键。本文不声称已验证任意受力姿态下的 reset 或自由坐姿恢复。

## 诊断负载与判据

每个规模收集 144 个测量控制周期，即每环境 2.4 s 仿真时间。单环境执行 `a`；多环境的偶数行触键、奇数行保持静止。部分触键行另有明确记录的软件丢失或最终读数缺失。第 0 行局部重置产生额外一个取消回合。

所有工位都运行物理、安全、事件和反馈逻辑。混合负载用于区分错误路由和广播；吞吐不是“所有工位同时进行任意接触动作”的通用上限。验收分别检查：

1. 完整原始样本数、严格时间与代际覆盖；每个控制动作覆盖相应的 4 个物理子步。
2. 静止行没有输入事件；触键行只有一次真实 `a` 的完整按下与持续释放；所有实体键都被监测。
3. 每行文本与反馈依据外部冻结设置独立回放，软件丢失/缺失只影响指定行，不能把物理成功直接当成数字成功。
4. 回合身份、动作所有者、原始观察、已到达读数、预算和最终结果相互绑定。
5. 局部重置不影响其他工位，旧令牌失效，旧请求不能出现在新回合。
6. 工位世界位置、零键帽目标、固定关节目标、关节/接触/姿态安全和接触缓冲错误检查均通过。

不以 worker 的退出码或控制器的“完成”作为成功证据。缺失 manifest、原始文件/来源哈希不符、数据空洞、缓冲溢出、显存不足或超时都不通过；失败目录保留。

## 吞吐和资源口径

主要吞吐为：

```text
每秒环境转移数 = 环境数 × 测量控制周期数 /（测量循环时间 + 最后一个原始块的刷新时间）
```

这不是物理子步/秒；控制每次推进 4 子步。测量循环包含物理、安全、CPU 传输、事件处理、反馈过滤和压缩原始块写入。另记录批步/秒、P50/P95 延迟和各部分耗时。

启动、资产转换、稳定和最终回合 JSON 序列化不包含在主要吞吐分母中；总 worker 时间另列。无模型推理、梯度更新或渲染，结果不等于 PPO 训练速度。每规模为一次有固定负载的工程诊断，不是多次重复的性能统计结论。

资源同时记录 Torch 分配峰值、进程 RSS 峰值，以及外部采样的 GPU **进程总占用**和设备总占用。GPU 总占用包含 PhysX/渲染运行时等非 Torch 内存；约 2 s 采样间隔可能遗漏瞬时峰值，因此标为采样峰值。设备占用也可能含桌面进程，不当作本任务独占。默认接触缓冲容量随配置和报告一起保存；没有通过调小记录频率来增加成绩。
