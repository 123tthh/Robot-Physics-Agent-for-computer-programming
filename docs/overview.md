# 项目总览

本项目构建 **Verifier-Grounded Agent–Skill Runtime**：人形机器人操作实体计算机，每个技能的完成与交接都由独立证据决定。仓库包名为 `vskill_os`；“Robot–Physics–Agent”、学习系统和 RSI 是同一项目的不同视角，不另建互不兼容的运行时。

## 目标与首个闭环

最终任务是接收目标、到达工位、建立稳定工作姿态，通过实体键盘和屏幕完成软件任务，并在失败后局部恢复。

当前研究主线定为**面向实体计算机操作的验证反馈驱动技能学习**，近期最小闭环是固定工位、单臂单手、少量可达字符键与退格键：

```text
单键接近—按下—释放 → 少量键的直接关节学习
→ 按证据历史选择继续输入 / 请求验证 / 恢复 / 请求结束
→ 独立评估短串正确性、物理释放与时间/验证成本
```

第一轮研究聚焦 4–8 字符串和强规则基线的公平对照；完整软件任务、视觉泛化、双手、自由坐姿与导航按证据逐级扩展。阶段说明见根目录的[研究工程架构](../verification-feedback-skill-learning/README.md)。已有 IK 演示继续作为明确标注的对照，不充当新学习策略的成果或示范数据。

## 架构不变量

- Agent 只请求 L2/L3 技能，不能生成关节命令。
- Skill 有版本、前置条件、后置条件、资源、失败码和有限时域。
- 控制器返回声明和原始证据；只有 Verifier 可以授权写入派生事实。
- 物理、GUI、软件证据分别验收，完成文本不能替代测试结果。
- 策略与安全检查分离，仿真和真机使用相同技能契约。
- 学习只能产生候选；晋升、回滚和运行中的控制权切换独立管理。

核心研究问题是：当物理触键与数字结果不一致、反馈不完整且验证有成本时，证据历史能否帮助策略更好地选择输入长度、验证时机与恢复动作。研究假设和实现状态分开记录；单次录像、替身测试和接口存在都不自动升级为完整能力。

## 从哪里开始

1. 按[子项目登记](WORKSTREAMS.md)选择工作范围与后端。
2. 按[路线图](ROADMAP.md)领取一个有明确退出门槛的任务。
3. 检查[分支登记](BRANCHES.md)和实时 Git 状态，确定任务所需代码实际位于哪里。
4. 完成后更新专项任务证据和子项目登记；只有跨项目优先级变化才更新路线图。
