# G1 + 双 Dex5-1：不使用 IK 的学习训练路线

调研日期：2026-09-23。状态：**研究方案，尚未实现训练环境、启动训练或产出新策略**。现有录像仍是学习平衡与手部 IK 的混合控制基线，不能标注为本方案的结果。

## 结论与边界

建议在现有 Isaac Sim 5.1 / Isaac Lab 2.3.2 中，以**直接输出关节目标的 PPO**作为工程起点：先学习单指触键与释放，再扩展到双手十指和未见过的短字符串；同时把站立到坐下建成独立学习技能，最后验证一次连续的“站立—坐下—打字—读取屏幕”。视觉学生策略和多任务生成策略安排在物理触键成功之后。

这里采用严格的无 IK 定义：训练、初始化数据生成、示范数据和部署都不调用逆运动学；不使用 IK 轨迹做行为克隆，不使用“IK 主动作 + RL 残差”。现有 IK 录像只作为外部效果比较，不进入新策略的训练集。上游预训练平衡网络的数据来源尚未完成同等审计，因此复用它的实验只能标注为“本地运行路径无 IK，预训练来源待审计”。要声称全过程来源也无 IK，需完成来源核查或重新训练坐下/平衡策略。

PD 电机驱动、关节限位和速度限制仍保留。读取仿真位置或用正运动学计算奖励距离不属于 IK；从指尖目标反求关节角则属于 IK。本方案首轮也不引入任务空间力控制或雅可比转置压键辅助，以便确实检验学习策略能否产生接触。

## 学习控制设计

### 动作与控制权

| 阶段 | 学习策略动作数 | 控制范围 |
|---|---:|---|
| 单臂单手触键 | 23 | 7 个臂/腕关节 + 16 个手部独立驱动 |
| 双臂双手打字 | 46 | 两组 23；下肢/腰部另由冻结的 15 维策略控制 |
| 全身联合训练 | 61 | G1 29 + 双手 32；8 个从动坐标不另发动作 |

不得把 Stay Seated 的 29 维身体策略与 46 维上肢策略直接叠加：两者会同时控制手臂。采用 15 + 46 时控制集合必须互斥；联合微调时则由一个 61 维控制器统一负责。

首选有界关节增量：`q_target = clamp(q_target_prev + action_scale * tanh(policy_output), joint_limits)`，再施加速度限制，通过真实关节驱动执行。动作范围、限速和 PD 参数必须记录；不写入关节实际位置，不给骨盆施加外力。关节目标绝对值映射作为动作参数化对照。首轮不使用额外任务空间辅助；可单独测试关节重力前馈，并记录它的开关。

建议起点为物理 200 Hz、策略 50 Hz，与现有仿真节奏一致。这是项目实验选择，不是 RoboPianist 的频率复现。事件桥应在每个物理子步更新，保留策略间隔内全部 KeyDown/KeyUp，而非只查看每四步末态。

### 观测与奖励

先训练有仿真状态的教师：关节角/速度、上一动作、躯干姿态与角速度、目标键和目标手指、后续少量字符、键帽行程、指尖相对键的位置、接触状态。critic 可额外读取椅子位姿、支撑力等。此阶段必须标注为特权状态策略，不宣称依靠相机完成任务。

任务奖励应以正确目标键 **按下并释放** 后的进度为主，辅以指尖接近和键程的连续奖励。惩罚误键、多键、接触过大、闲置手指碰撞、动作抖动、关节极限、能耗以及椅子意外滑动。每次事件只计一次；同一键保持按住、反复抖动、按错后补对都不能刷进度。连续相同字符必须释放后重新按下。

指尖距离用于计算奖励，不转换成关节指令。初始任务提供固定指法，使两个拇指和八个其他手指都参与；否则优化器可能只学会双食指。后续再研究自动指法分配，不把“训练成功”与“十指覆盖”混为一谈。事件状态机只维护目标进度，不提供伸手、下压、抬手的关节轨迹。

视觉阶段使用 RGB-D + 本体观测 + 字符目标的学生策略，教师由上述已训练的关节策略提供监督，再做 DAgger/强化学习修正。不能悄悄给视觉 actor 输入真值键位、接触力或由真值定位的图像裁剪。传感器不可用的量仅供训练 critic/教师和离线分析使用。

### 独立的坐下技能

建立站立到接触座面的短时程 PPO 任务。先固定椅子几何和桌椅相对位置，学习骨盆靠近座面、受控降速、脚底支撑、座面承重与稳定保持；惩罚落座冲击、脚滑、椅子失控、碰桌和失衡。奖励允许根据物理状态变化，但不预先给骨盆下降轨迹、IK 姿态序列或学习策略之外的外力支撑。

可先训练身体 29 维动作，手指以直接关节目标保持张开；该技能完成后向打字控制器交接。交接必须检查关节目标连续性、支撑与椅速，不能在同一控制周期让两套策略竞争手臂。随后通过接续状态采样和联合微调降低两个技能之间的状态分布差异。

课程可从近座面的有效状态向站姿扩展，但需来自直接关节初态或无 IK 物理 rollout，并标记 reset；最终只从站姿统计完整成功率。先实现稳定坐下与静止打字，再把载人椅移动作为独立技能加入。

## 最小实验和推进门槛

以下数值全部是**拟定预算与验收目标，尚无测量结果**。

| 阶段 | 最小实验 | 进入下一阶段的条件 |
|---|---|---|
| E0 环境正确性 | 1/16/64 环境，零动作、关节限速、受控单键事件检查；审计无 IK 依赖 | 无环境间事件串扰、无接触缓冲区溢出；8 个从动坐标映射正确；从物理记录可重建全部事件 |
| E1 单指 | 单臂单手 23 维，先一个键的按下/释放，随后轮换五指；另一只手保持无碰撞姿态 | 每个配置 3 个训练种子，各 100 个独立评估回合；各目标指单键完整成功率目标 ≥95%，报告置信区间和失败例 |
| E2 双手十指 | 扩至 46 维，先固定十指串 `asdf jkl; `，随后训练可达键集中的随机短串 | 十指固定串完整成功率目标 ≥90%；全部键释放且无额外事件；不能以平均单键成功率代替整串成功率 |
| E3 坐下与接续 | 单独训练坐下，然后从站姿连续运行坐下 + E2；逐步加入椅子扰动 | 独立验证坐下、交接和触键；不 reset、不托举；报告整体成功率及接触冲击，不只报告两个子技能的成绩 |
| E4 泛化/屏幕 | 未见字符序列、重复字符、空格/回车/退格、可达范围内键盘偏移；接入真实屏幕验收 | 训练/验证/测试分离；报告精确事件序列、文本编辑距离、最终释放和相机读取结果 |
| E5 视觉与全身 | 无 IK 教师蒸馏视觉学生，必要时 61 维联合微调 | 学生评估不使用特权观测；明确相比状态教师的性能下降与新失败类型 |

最早阶段可暂时限制动作维度或固定部分关节目标降低探索难度，但必须通过 PD 保持，不得固定根部后把结果称为自由坐姿打字。若另建固定台架诊断任务，其结论仅对诊断任务有效。

E1 先用聚合 100 万环境转移检查是否能学到接近/释放，再决定是否继续到 1000 万；预算是所有并行环境转移之和，不是优化器迭代数。首次只跑一个种子验证任务设计，方案冻结后用 7、17、27 三个独立种子比较。没有事件进展时先检查接触、动作映射和奖励，不盲目扩大网络或继续耗算力。

可用 PPO 起始候选：MLP `[256,256,128]`，rollout 24，学习率 `3e-4`，clip `0.2`，gamma `0.99`、GAE lambda `0.95`。这些是待调参起点，不是已经验证适配 Dex5 的超参数。完整记录归一化、随机种子、奖励版本、采样数、恢复点和成功/失败轨迹。

建议最小消融：固定指法/自由分配、接触与键程塑形/只有事件奖励、观测历史开/关、域随机化开/关。后续比较冻结下肢/联合训练，以及直接 PPO/无 IK 学习专家数据预训练 + PPO。旧 IK 基线仅用于报告效果差异。

## 训练工程与算力核查

本机已有 Isaac Lab 2.3.2 源码和 RSL-RL 3.1.2。安装包内部版本分别为 `isaaclab 0.54.2`、`isaaclab-tasks 0.11.12`，与发行目录名不是同一种版本编号；Torch 为 `2.7.0+cu128`。选择 PPO 是为了优先使用已安装的并行训练框架，并不表示论文已证明它优于 DroQ。

本地 `inhand_manipulation_env.py` 的 `_apply_action()` 已有“缩放动作—平滑—限位—`set_joint_position_target`”范式。可参考该实现建立新任务；[官方环境目录](https://isaac-sim.github.io/IsaacLab/v2.3.0/source/overview/environments.html)中的 Allegro/Shadow 任务不是 Dex5 打字成品。一些 G1 操作示例虽包含学习平衡，也仍使用上肢 IK，不能直接满足本要求。

现有演示是单环境脚本，需要提取可批处理的机器人、椅子、键帽、接触与事件桥。每个环境独立维护字符进度、迟滞和释放状态；不要在 GPU 策略循环里按环境执行 SciPy 或 `.cpu().numpy()`。当前下肢 ONNX 推理和历史缓存也需批处理，并回归比较输出。

RTX 5090 的有效环境数与速度尚未测量。先逐级测 16、64、128、256 环境的聚合 transitions/s、峰值显存、接触完整性与训练更新时间，出现资源/物理问题即停止扩大。用实测吞吐量估算预算，不承诺“几小时训练成功”，不照搬其他论文的上千环境配置或 FPS。

状态训练关闭画面与 PTY；低频保存少量评估录像。视觉学生阶段再启用相机并重新测吞吐量。随机化应在基础任务成功后加入：键簧/阻尼、摩擦、执行器强度/延迟、传感噪声、键盘位置、椅子质量/脚轮阻力；范围要符合机构可达性和物理参数，不用不可完成样本制造“鲁棒性”。

## 验收、复现与尚未解决的问题

保留 Agent → 有限时域 Skill → 可替换策略 Adapter → 关节驱动的分层。Agent 只指定坐下或输入文本，不生成关节动作。建议新技能预发布版本 `0.1.0`，记录站姿/坐姿前置条件、机器人和键盘资源占用、期望事件/释放后置条件，以及 `NO_CONTACT`、`WRONG_KEY`、`STUCK_KEY`、`LOST_SUPPORT`、`TIMEOUT` 等失败码；名称和契约须在实现时与现有核心模型对齐。

独立 Verifier 根据保存的物理接触、键程、事件和屏幕结果判定，不接受策略自报成功或奖励阈值代替证据。低层限位、速度/力矩限制、姿态/碰撞守卫独立于策略；强烈碰撞、跌倒或失控立即终止训练回合。评估报告写“本批回合观察到零安全失败”，不能据此承诺绝对安全。

每次实验应记录代码/资产/配置哈希、物理引擎和驱动版本、训练种子、评估种子、学习曲线、checkpoint、归一化状态、事件日志及完整连续录像。固定种子复跑之外，还需多种子与未见扰动验证；GPU RL 不承诺逐位相同。
