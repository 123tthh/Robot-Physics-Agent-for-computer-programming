# Unitree G1 29DOF / 5010 配置基线

## 结论

“G1 29DOF 5010”不能唯一确定动力学模型。Unitree 当前官方描述至少列出五个 5010 腕部电机版本；髋关节减速比、腰部锁定状态和 `mode_machine` 不完全相同。任何策略权重、URDF/MJCF、PD 参数和真机部署配置都必须携带兼容性标识。

| `mode_machine` | 官方资产 | 髋 pitch/roll 减速比 | 腰部 |
|---:|---|---|---|
| 13 | `g1_29dof_mode_13` | 14.3 / 22.5 | 未锁定 |
| 14 | `g1_29dof_mode_14` | 14.3 / 22.5 | 锁定 |
| 15 | `g1_29dof_mode_15` | 22.5 / 22.5 | 未锁定 |
| 16 | `g1_29dof_mode_16` | 22.5 / 22.5 | 锁定 |
| 18 | `g1_29dof_mode_18` | 22.5 / 22.5 | 未锁定 |

来源：[Unitree G1 Description](https://github.com/unitreerobotics/unitree_ros/blob/master/robots/g1_description/README.md)。实际 `mode_machine` 应在 Unitree App 的 `Device > Data > Robot > Machine Type` 查看。

## 本项目的防错策略

配置文件为 `configs/robots/g1_29dof_5010.json`：

- `simulation_mode_machine=15` 只是当前纯仿真的显式默认值；
- `selected_mode_machine=null` 使真机适配器默认不可启用；
- 真机接入时必须填写实际 Machine Type，并再次读取运行时观测确认；
- mode、29 个身体关节和 5010 腕部任一不符即拒绝加载策略；
- 腰部锁定版本不能沿用未锁定版本的坐下或全身控制权重。

查看当前配置：

```bash
PYTHONPATH=src python3 -m vskill_os.cli inspect-robot

PYTHONPATH=src python3 -m vskill_os.cli inspect-robot \
  --policy-manifest configs/robots/g1_29dof_mode15_policy.example.json

PYTHONPATH=src python3 -m vskill_os.cli inspect-robot \
  --policy-manifest configs/robots/g1_29dof_mode15_seated_policy.example.json
```

## 策略产物必须携带的元数据

```json
{
  "robot": "unitree_g1",
  "body_dof": 29,
  "mode_machine": 15,
  "wrist_motor": "5010",
  "waist_locked": false,
  "hip_gear_ratio": [22.5, 22.5],
  "joint_order": ["left_hip_pitch", "...", "right_wrist_yaw"],
  "action_type": "joint_position_target",
  "control_hz": 50,
  "low_level_hz": 500,
  "simulator": "isaac_sim",
  "simulator_version": "pinned-by-training-run",
  "training_commit": "required"
}
```

`compatibility_key` 由代码生成，例如：

```text
g1-29dof-mode15-wrist5010-hip22.5x22.5-free
```

只有兼容性键完全一致的策略才能进入 hardware adapter。

坐姿移动策略还必须通过 `SeatedLocomotionPolicyManifest` 校验：actor
严格为 96 维本体感觉与速度命令，座椅/接触等仿真特权量只允许出现在
critic 的额外观测中，总 critic 维数为 217。清单同时固定无动力座椅结构、
训练终止阈值和 SY/FS/CC 训练组合；FS 单独启用时会暴露静止局部最优风险标记。

## 仿真版本隔离

- [Unitree Sim IsaacLab](https://github.com/unitreerobotics/unitree_sim_isaaclab) 提供与真机相同的 DDS 边界及 G1 + Dex3 任务，但其 README 当前对 RTX 50 系建议 Isaac Sim 5.0；
- [WBC-AGILE](https://github.com/nvidia-isaac/WBC-AGILE) 当前锁定 Isaac Lab 3.0.0-beta2、Isaac Sim 6.0、Python 3.12，且已有 G1 sit-down/stand-up；
- 因此不应把两套依赖强行装在一个 Python 环境。V-Skill OS 只通过 adapter 协议连接它们，训练环境各自锁版本和 commit。

### P1 固定资产清单

`configs/simulation/g1_29dof_5010_p1.json` 是当前唯一 P1 仿真入口：

- `mode_machine=15`、29 个身体关节、5010 腕部、腰部未锁定；
- 固定基座，Agent 不能直接发关节命令；
- Unitree `g1_29dof_mode_15.urdf` 使用完整 commit 和 SHA-256 固定；
- 针对当前 RTX 5090 主机实测并固定 Isaac Sim 5.1.0、Isaac Lab 2.3.2（Python 包 0.54.2）及 commit `37ddf626871758333d6ed89cf64ad702aef127d0`；
- `hand_assets_enabled=true`，目标资产为 mode 15 / 5010 body + 双 Dex3，共 29+14 个主动关节；
- 74 个键帽使用独立 4 mm 棱柱关节和 PhysX 接触报告，驱动现有事件桥与 PTY；
- 头部和键盘两路 1280×720、全景一路 960×540 RTX RGB 相机已完成非空、有限值、渲染产物哈希健康检查。

Dex3 资产包及 mode 15 / 5010 组合 URDF/USD 已成为 P1 默认资产；详见
[`DEX3_ASSET_AUDIT.md`](../experiments/dex3/DEX3_ASSET_AUDIT.md)。

P1 已在本机完成 URDF→USD、OpenUSD 依赖、PhysX 启动、关节运动、键帽接触、相机与 PTY 验收，`physics_validation=verified_local_isaac_runtime`。耐久化证据位于 `reports/isaac_p1_acceptance.json`；它不代表 P2 的 Dex3 指尖打字或 sim-to-real 已通过。

## 真机启用前检查表

1. 在 App 读取并记录 Machine Type；
2. 对照机器人铭牌/BOM确认腕部为 5010；
3. 读取 SDK 关节状态长度与顺序；
4. 校验策略的兼容性键、归一化参数、PD 参数和控制频率；
5. 吊具状态下完成零命令、单关节方向和急停测试；
6. 再启用站立策略；
7. 导航、坐下、上肢、灵巧手按控制权逐层开放，禁止一次性全开。
