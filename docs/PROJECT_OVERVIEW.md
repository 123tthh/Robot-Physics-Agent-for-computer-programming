# 项目总览

## 目标

构建运行于 Unitree G1 的 Verifier-Grounded Agent–Skill 系统，使机器人通过实体键盘和光学屏幕操作数字代码智能体，并根据物理、GUI 和软件证据独立判断任务是否完成。

核心任务闭环：

```text
用户目标
→ 高层 Agent 分解任务
→ 调用带契约的 Skill
→ 机器人/键盘/屏幕/Codex 执行
→ 独立 Verifier 检查状态
→ 事件账本记录证据
→ 成功推进或调用恢复 Skill
```

## 科学主线

1. **可验证技能交接：**区分动作完成、局部后置条件、下一技能就绪性和任务语义完成；
2. **跨域验证：**统一物理状态、GUI 状态和软件执行状态；
3. **结构化恢复：**根据失败码、证据和恢复记忆进行局部修正或重规划；
4. **任务约束全身模仿：**让坐下与工作姿态同时满足多接触稳定、屏幕可见、双手可达和指尖精度；
5. **实体计算机使用评测：**系统化注入按键、焦点、姿态、代码和中断故障。

## 系统边界

高层 Agent 只调用 L2/L3 Skill，不输出关节指令。高频控制、碰撞停止、防跌倒和力限制位于独立安全层。Codex 运行在隔离环境中，且“声称完成”不能替代测试证据。

## 构建依赖

```text
工程骨架与事件账本
→ 固定坐姿键盘 MVP
→ Agent–Codex–Verifier 闭环
→ 学习式按键 Skill
→ 坐下与工作姿态策略
→ 导航和全身端到端集成
→ 故障注入、消融与论文评测
```

这是依赖顺序，不代表时间安排。固定坐姿 MVP 必须先证明 `press_chord → terminal_ready` 和“测试失败—请求修复—重新验证”的闭环。

## 首个端到端任务

在固定稳定工作姿态下，G1 打开终端并启动 Codex，要求创建 `hello.py`，执行自动测试；若代码错误则向 Codex 反馈错误信息并要求修复，只有测试通过后才报告任务完成。

## 主要模块

| 模块 | 职责 |
|---|---|
| `agent_orchestrator` | 任务分解、Skill 选择、重规划 |
| `skill_registry` | Skill 发现、契约和版本管理 |
| `skill_runtime` | 前置检查、资源锁、执行、取消和结果统一 |
| `multimodal_verifier` | 证据融合和状态验证 |
| `event_ledger` | 任务状态、调用、证据和检查点 |
| `recovery_manager` | 失败码和恢复 Skill 路由 |
| `whole_body_control` | 坐下、起身和任务约束工作姿态 |
| `keyboard_manipulation` | 键盘标定、视觉伺服和按键控制 |
| `codex_sandbox` | 数字 Agent 隔离、代码版本和测试 |
| `evaluation_harness` | 故障注入、基线、消融和指标 |

## 首篇工作的建议贡献

优先收敛为：**V-SkillGraph、下一技能就绪性和跨物理—GUI—软件故障恢复**。导航、坐下与全身模仿作为可插拔 Skill 接入；若全身控制方法足够完整，可单独形成任务约束运动模仿方向的工作。
