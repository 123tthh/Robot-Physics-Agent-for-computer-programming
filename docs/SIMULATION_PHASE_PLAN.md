# 仿真专项分阶段实施规划

状态快照：2026-09-04。本文把项目 P0–P6 的总体能力规划重新组织为可逐项验收的仿真路线图。业务执行顺序仍是“进入房间 → 导航 → 对椅 → 坐下 → 操作电脑 → 验证软件任务”，但工程实施顺序优先关闭固定基座触键和软件闭环，再开放坐下与导航，以便把失败定位到单一能力边界。

## 1. 总体目标与边界

仿真系统用于验证四类相互独立但可组合的能力：

1. 物理世界：G1、双 Dex3、房间、桌椅、键盘、碰撞和接触；
2. 控制执行：导航、对椅、坐下、工作姿态、指尖触键和恢复；
3. 数字环境：键盘事件、终端、代码 Agent、文件与测试；
4. 独立验证：物理、GUI、软件和安全证据共同决定状态是否可推进。

始终遵守以下边界：

- Agent 只调用 L2/L3 Skill，不输出关节、力矩或高频速度命令；
- 控制器只能声明动作完成，只有 Verifier 能写入已验证任务状态；
- Isaac 真值、事件桥内部状态和文件 API 是开发 Oracle，不自动等于论文或真机可观测证据；
- Isaac、ROS 2、模型和厂商依赖留在 Adapter 或独立 worker，核心领域模型保持轻量；
- 每次只新增一种主要控制能力或扰动类型，并保存版本、资产哈希、场景种子和报告；
- 仿真通过、HIL 通过和真机通过必须使用不同能力等级，禁止互相替代。

## 2. 状态与证据等级

### 2.1 任务状态

| 状态 | 定义 |
|---|---|
| `DONE` | 产物存在，自动验收和人工/可观测门槛均满足 |
| `PARTIAL` | 已有资产、接口或诊断结果，但阶段退出条件未完全满足 |
| `READY` | 前置依赖已经满足，可开始实现 |
| `PLANNED` | 依赖或实现尚未完成 |
| `BLOCKED` | 缺少明确的外部资产、运行时、硬件、权限或验证工具 |

### 2.2 能力等级

```text
C0 契约/静态配置
→ C1 纯 Python 回放
→ C2 OpenUSD 拓扑与资产检查
→ C3 Isaac PhysX 动态验证
→ C4 与真机一致的视觉/接触可观测验证
→ C5 HIL
→ C6 真机
```

阶段报告必须标注达到的最高等级。例如 P1 当前达到 C3，但导航策略和真实坐下仍未达到 C3；P2 虽有自动事件诊断，因可见实体触键尚未确认，仍保持 `PARTIAL`。

## 4. 各阶段详细任务

### SIM-00：契约、证据与确定性回放

映射：P0。状态：`DONE`，后续持续回归。

任务：

- `SIM00-T01`：固定 Skill 输入、前置/后置条件、资源、失败码和版本；
- `SIM00-T02`：定义 Isaac、desktop、model worker 的请求、进度、取消、结果和健康协议；
- `SIM00-T03`：建立物理、GUI、软件、安全四域 Evidence 和来源隔离；
- `SIM00-T04`：实现状态 TTL、依赖失效、检查点、故障注入和恢复回放；
- `SIM00-T05`：为后续真实 Adapter 保留同契约 fake 实现。

退出门槛：重复、乱序、过期、超时和 worker 崩溃都不能错误推进状态；控制器完成消息不能绕过 Verifier。

证据：`make check`、`make demo`、`make demo-mixed`、`make benchmark`。

### SIM-01：机器人、灵巧手与办公场景资产

映射：P1、P4-T01、P5-T02 静态资产部分。状态：`DONE`（资产级）。

任务：

- `SIM01-T01`：锁定 G1 29DoF、`mode_machine=15`、5010 腕部和 29 个身体关节；
- `SIM01-T02`：组合左右 Dex3-1，校验 14 个手关节、网格、惯量和碰撞；
- `SIM01-T03`：构建 74 键带高对比标识的独立键帽和 4 mm 键程；
- `SIM01-T04`：构建 0.4775 m 座高的五脚移动椅、完整桌架和显示器；
- `SIM01-T05`：构建 8×6×2.8 m 四墙房间、1.2 m 门洞、A/B/C 三工位、3 个出生点、12 个导航锚点和静态障碍；
- `SIM01-T06`：固定资产来源、许可证、哈希、单位、Z-up、默认 prim 和兼容性 Manifest；
- `SIM01-T07`：保存总览、头部和键盘视角渲染证据。

退出门槛：

- 29+14 个主动关节、74 个键帽关节和所需碰撞体精确匹配；
- 房间 4 个逻辑墙面/6 个碰撞段、3 个唯一工位和 12 个锚点完整；
- 移动椅无世界固定关节，120 N 探针可产生位移并保持滑动主导；
- 项目级 OpenUSD 检查通过，同时不冒充正式 NVIDIA SimReady 认证。

当前产物：

- 场景：`artifacts/isaac-p1/scenes/p1_g1_dex3_keyboard.usda`；
- 房间配置：`configs/simulation/p1_navigation_room.json`；
- 资产链配置：`configs/simulation/p0_p1_workstation_asset_chain.json`；
- 报告：`reports/isaac_p1_acceptance.json`、`reports/isaac_p1_workstation_validation.json`。

### SIM-02：PhysX、相机、键盘事件与 PTY

映射：P1。状态：`DONE`。

任务：

- `SIM02-T01`：建立键帽 Released/Contact/Actuated/Held/Releasing 状态机；
- `SIM02-T02`：实现按下/释放迟滞、防抖、最长保持和统一释放；
- `SIM02-T03`：把物理键帽样本桥接为 `KEYDOWN/KEYUP`；
- `SIM02-T04`：连接 Pygame/PTY，区分事件、焦点、画面和字符流来源；
- `SIM02-T05`：接入头部、键盘和总览 RTX RGB 相机；
- `SIM02-T06`：覆盖邻键接触、重复/乱序样本和 worker 故障恢复。

退出门槛：一次完整物理按压只产生一对 Down/Up；`Ctrl+Alt+T` 可打开并聚焦 PTY；结束后无残留按键；三路相机输出非空有限图像。

证据：`make demo-p1`、`make isaac-p1`、`make isaac-p1-validate`。

### SIM-03：Dex3 单指与双手可见触键

映射：P2。状态：`PARTIAL`，当前最高为自动化诊断，不是阶段完成。

任务：

- `SIM03-T01`：校准 Dex3 指尖碰撞点、腕—手—键盘坐标和安全工作空间；
- `SIM03-T02`：完成单键 hover → approach → contact → actuate → release 基线；
- `SIM03-T03`：将 DLS/IK、混合位置—力控制封装在 Isaac Adapter 内；
- `SIM03-T04`：完成模块化 ActionGraph 的 prepose、keydown、hold、keyup、group release 和 screen gate；
- `SIM03-T05`：关闭 `Ctrl+Alt+T` 双手组合键的可见物理动作门槛；
- `SIM03-T06`：加入邻键误触、过力、漏触、卡键、手碰撞风险和统一释放；
- `SIM03-T07`：从精确 Isaac Oracle 迁移到相机/接触可观测 Verifier；
- `SIM03-T08`：扩展短字符串、Shift/符号、退格修复和每键成功矩阵。

退出门槛：相机或 GUI 能复核指尖真实压下目标键；目标键接触、键程、唯一事件、屏幕结果与释放一致；无邻键误触，峰值力不超过门限；ActionGraph 不含关节命令。

当前证据：`make demo-p2`、`make isaac-p2` 和 `reports/isaac_p2_acceptance.json`。现有报告不能替代可见动作复核。

### SIM-04：终端与真实代码 Agent 混合仿真

映射：P3。状态：`PARTIAL`。

任务：

- `SIM04-T01`：实现真实代码 Agent 的启动、提交、观察、取消、继续和关闭 Adapter；
- `SIM04-T02`：用容器或虚拟机替代当前固定模板沙箱；
- `SIM04-T03`：记录会话、工作区、产物清单、哈希、测试命令、退出码和日志；
- `SIM04-T04`：建立终端可见、忙碌、等待输入、报错和完成候选的 GUI/OCR 状态；
- `SIM04-T05`：完成首稿失败 → 最小错误摘要 → 请求修复 → 独立复测；
- `SIM04-T06`：覆盖焦点丢失、进程退出、超时、网络中断和修复预算耗尽。

退出门槛：代码 Agent 的“完成”文本不能直接通过；错误程序必须被独立测试器拒绝，修复后才能报告成功；不可信代码不能直接在宿主机任意执行。

### SIM-05：对椅、坐下、载人椅子和工作姿态

映射：P4。状态：`PARTIAL`，资产完成，真实动态策略未完成。

任务：

- `SIM05-T01`：补充固定椅变体和骨盆、靠背、双足、脚轮接触传感器；
- `SIM05-T02`：接入 WBC/运动模仿策略 Adapter，并绑定精确 G1 Manifest；
- `SIM05-T03`：实现 chair_alignment → pre_sit → contact_transition → stabilize；
- `SIM05-T04`：验证冲击、脚滑、椅滑、接触不足、躯干倾角和失败回退；
- `SIM05-T05`：实现有限时域坐姿椅子重定位，并在移动后重新稳定；
- `SIM05-T06`：联合验证坐稳、屏幕可见、双手可达和键盘标定有效性；
- `SIM05-T07`：随机化座高、椅重、摩擦、桌距和初始对齐误差。

退出门槛：不能只凭臀部接触判定成功；必须同时满足骨盆—座面接触、双足接触、躯干/椅子倾角、低速度、屏幕视野和双手可达。工作姿态一旦失效，打字 Skill 必须暂停并使相关状态失效。

### SIM-06：房间入口到多工位导航

映射：P5-T01/T02。状态：`PARTIAL`，房间和工位资产已完成。

任务：

- `SIM06-T01`：固定占据地图/导航网格生成规则及场景版本；
- `SIM06-T02`：实现 `navigate_to_workstation(workstation_id)` L3 契约；
- `SIM06-T03`：接入定位、全局规划、局部避障与 `{vx, vy, yaw_rate}` 限幅 Adapter；
- `SIM06-T04`：从 3 个出生点分别导航到 A/B/C 工位；
- `SIM06-T05`：到站后进入 `workstation_approach` 和 `chair_alignment` 容差域；
- `SIM06-T06`：加入固定阻塞、可复现动态障碍、重规划和超时恢复；
- `SIM06-T07`：由独立定位、目标姿态、速度稳定性和碰撞净空验证到站；
- `SIM06-T08`：接入文本命令，再接预录语音和本地麦克风入口。

退出门槛：导航控制器不能自己写入 `workstation_reached`；三个出生点/三个工位组合均有成功率与失败分类；阻塞、定位丢失、无法规划和未稳定均返回结构化失败码。

### SIM-07：端到端办公任务联合场景

映射：P2–P5 集成。状态：`PLANNED`。

任务：

- `SIM07-T01`：组合“进入房间 → 工位 A → 对椅 → 坐下 → 打开终端 → 输入任务 → 独立测试”；
- `SIM07-T02`：在每个 Skill 交接处验证下一技能就绪性；
- `SIM07-T03`：实现导航、坐姿、触键、焦点和软件失败的局部恢复；
- `SIM07-T04`：验证恢复不会无条件重做已通过的危险接触转换；
- `SIM07-T05`：加入取消、人工接管、超时和统一安全停止；
- `SIM07-T06`：输出按任务、Skill、证据域和恢复成本分解的报告。

退出门槛：至少一个短代码任务在固定种子下完成全链路；任何控制器声明都不能跳过 Verifier；失败可定位到具体 Skill、状态、证据或交接条件。

### SIM-08：随机化、数据采集、训练与评测

映射：P2、P4、P5、P6。状态：`PLANNED`。

任务按由易到难的顺序启用：

1. 键盘平移/偏航、相机外参和标定噪声；
2. 键程、弹簧、阻尼、摩擦、指尖接触和机构回差；
3. 光照、遮挡、屏幕反光、OCR 噪声和分辨率；
4. 控制延迟、通信抖动、丢帧、worker 重启和焦点扰动；
5. 桌椅尺寸、质量、摩擦、座高、初始姿态和接触扰动；
6. 导航布局、出生点、固定/动态障碍和重规划条件。

实施任务：

- `SIM08-T01`：定义场景参数、种子、课程难度和数据 Manifest；
- `SIM08-T02`：采集遥操作/基线轨迹，保存观测、动作、Oracle 和独立 Evidence；
- `SIM08-T03`：训练受限指尖残差、坐下/工作姿态或导航策略；
- `SIM08-T04`：建立 train/validation/test 场景隔离和回归回放；
- `SIM08-T05`：执行无 Verifier、无恢复、无残差、单手/双手等消融；
- `SIM08-T06`：报告成功率、误触率、过力率、恢复代价、安全停止和人工接管。

退出门槛：候选策略在未见固定测试集上优于几何/规则基线，且不降低安全指标；任何学习策略都不能修改硬限制、Verifier 来源、Skill 权限或硬件身份门禁。

映射：P6。状态：`PLANNED`。

任务：

- `SIM09-T01`：校验真机 `mode_machine`、5010 腕部、关节顺序、频率、归一化和 Dex3 通信；
- `SIM09-T02`：实现仿真/真机共用 Skill 契约的 HIL Adapter；

## 5. 推荐实施顺序

以下是能力研发顺序，不是机器人运行时动作顺序：

```text
已完成：SIM-00 → SIM-01 → SIM-02
当前主线：SIM-03 可见 Dex3 触键
→ SIM-04 真实代码 Agent 闭环
→ SIM-05 坐下与工作姿态
→ SIM-06 多工位导航
→ SIM-07 端到端联合场景
→ SIM-08 随机化、数据和训练
→ SIM-09 HIL / 真机
```

SIM-05 与 SIM-06 的资产和接口工作可以交错，但重型策略训练不应在 SIM-03 的可见物理触键门槛关闭前成为主线。SIM-07 之前，坐下、导航和触键必须分别有独立场景及失败分类。

## 6. 每阶段统一交付物

每个 `SIMxx-Tyy` 至少交付：

- 版本化配置/Manifest；
- 核心契约或 Adapter 接口；
- 最小正常、失败、取消/恢复测试；
- 场景种子、资产哈希和运行时版本；
- 机器可读 JSON 报告；
- 必要的 PNG/视频/轨迹等可观察证据；
- 对应 Markdown 状态、能力等级和剩余风险；
- `make check` 与 `make demo` 回归结果。

重型 Isaac 任务还应记录 GPU、物理步长、控制频率、渲染设置、耗时和进程退出状态；一次只运行一个全量 Isaac 任务，结束后确认没有本项目残留进程。

## 7. 资产与 SimReady 流程

项目资产采用分阶段门禁：

```text
来源/许可证/版本
→ URDF、USD 或程序化几何生成
→ 最小 USD 可用性检查
→ 材质/物理属性赋值（需要时）
→ Profile 修复与正式验证（运行时齐备时）
→ PhysX 动态验收
→ 渲染检查
→ 场景集成与包清单
```
