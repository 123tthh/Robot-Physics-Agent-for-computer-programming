# P3：代码 Agent、终端和独立测试闭环

状态：`PARTIAL`

当前纯 Python 场景已经证明“代码 Agent 声称完成不等于测试通过”，但使用的是受控模板和模拟 Agent。

## 目标

在隔离环境中启动真实代码 Agent，提交任务，观察进度，独立验证产物；失败时提供最小充分证据并要求修复。

## 任务

### P3-T01：代码 Agent Adapter 契约

状态：`READY`

产物：

- 启动、提交、观察、取消、继续和关闭接口；
- 会话 ID、工作区 ID、进度和错误消息；
- 本地 fake Adapter 保持现有测试；
- 真实 Adapter 不进入核心领域模型。

验收：Agent 进程退出、网络中断、超时和空响应均映射为结构化失败码。

### P3-T02：隔离工作区和独立测试器

状态：`PLANNED`

产物：

- 容器或虚拟机隔离方案；
- 输入、输出和资源限制；
- 产物清单、哈希、测试命令、退出码和日志 Evidence；
- 禁止用代码 Agent 自己的测试声明作为唯一证据。

验收：错误 `hello.py` 被拒绝，修复后由独立执行器确认通过。

### P3-T03：屏幕观察和任务完成判读

状态：`PLANNED`

产物：

- 终端/代码 Agent 的可见、忙碌、等待输入、报错和完成候选状态；
- 画面采样频率与变化检测；
- OCR/VLM Adapter 和确定性基线；
- 数字 API Oracle 与相机证据分离。

验收：静止画面、模型完成文本和真正测试通过能够区分。

### P3-T04：失败—反馈—修复循环

状态：`PLANNED`

产物：

- 失败摘要包含测试命令、退出码和最相关错误；
- 修复轮次和预算；
- 检查点恢复；
- 达到预算后请求人工处理，而非无限循环。

验收：至少覆盖语法错误、错误输出、测试超时和 Agent 中断。

## 阶段退出条件

- 用 Pygame/PTY 或真实终端完成 hello world；
- 首稿失败后能修复并重新验证；
- 所有报告均可追溯到物理、GUI和软件 Evidence；
- 不可信代码不会直接在宿主环境任意执行。
